# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) starting with v1.0.0.

## [Unreleased]

### Fixed

- Status indicators (spinner / ✓ / ?): indicators were always dark when starting a new session for the first time. `SetGlobalEnv` silently failed when the tmux server didn't exist yet, so `SM4C_HOOK_FIFO` was never in the Claude process's environment and every hook script's guard no-oped. Fixed by adding a `GlobalEnv` field to `OneShot` and injecting `set-environment -g SM4C_HOOK_FIFO …` atomically into the `new-session` / `new-window` command chain before the window is created, covering both `sm4c` (bare, press `n`) and `sm4c [args]` entry points.

- Editor pane: closing nvim (`:q`) left the split open in sm4c's view and the tmux pane sitting idle. Root cause: the bridge was reading `out.Args[0]` as the pane ID from `%pane-exited`, but tmux's format is `$session session-name @window window-name %pane exit-status` — `Args[0]` is the session ID (`$N`), not the pane ID (`%N`). The `%` prefix check silently dropped every `%pane-exited` event. Fixed by scanning all args for the first token matching `%\d+`. Additionally, `handlePaneExited` now explicitly calls `KillPane` on the editor pane so any pane left open by `remain-on-exit` is closed.
- Hook scripts: Claude Code showed "x hook error: Failed with non-blocking status code: No stderr output" whenever a lifecycle hook fired outside an sm4c-managed session (SM4C_HOOK_FIFO not set). The `&&`-chained hook script exited 1 when the FIFO path was absent. Fixed by appending `; true` so the script always exits 0 — a no-op path is not an error. The updated command string triggers `installClaudeHooks`'s stale-detection on next startup, re-installing the corrected script automatically.
- Editor pane: even after the `%pane-exited` arg fix, pane exits could still be missed if the pane event reader was not re-armed — the `paneExitedMsg` Update case was returning without calling `waitForPaneEvent()`, so TUI event reading silently stopped after the first exit. Fixed by re-arming in the `paneExitedMsg` case. As an additional belt-and-suspenders: the session poll (1 s cadence) now checks `#{window_panes}` for each window; when a window that has a registered editor pane drops to 1 pane, `handlePaneExited` is triggered inline, so cleanup happens within one poll tick regardless of whether the pane event was received.

- Editor pane: session name in sidebar and right-pane header changed to the editor's title (e.g. "nvim") while an editor split was open. `#{pane_title}` reflects the active pane, which becomes the editor pane on open. Fixed by caching the claude pane's OSC title per window in `claudeTitleByWindow` and freezing updates to that cache while an editor pane is open for the window.
- Editor pane: claude view showed ANSI artifacts after the split opened because the VT emulator held stale full-width content being rendered at half-width. Fixed by dropping the emulator on `editorOpenedMsg` (shows "waiting for output" momentarily) and issuing a `resize-window` command so tmux redistributes the split and claude gets a SIGWINCH, producing a fresh redraw at the correct half-width.
- Editor pane: closing the editor left the claude view at half-width. `handlePaneExited` only resized the in-process VT emulator but never sent a tmux resize command. Fixed by also dropping the stale half-width emulator and issuing `resize-window` on exit, so claude gets a SIGWINCH and redraws full-width.

### Added

- Editor pane (`o` key): pressing `o` on a highlighted session opens the session's working directory in `$VISUAL` / `$EDITOR` / first of nvim, vim, nano found on `$PATH` as a vertical split alongside the claude pane. `Tab` swaps focus between the claude and editor panes while in pane-focus mode; `ctrl+b` always returns to the sidebar. The editor pane is sized to half the right-pane width; the VT emulators for both halves are resized on open and restored when the editor exits.

### Fixed

- Scrollback "page-flip overlay": when the user scrolled up, the live claude UI stayed anchored at the bottom of the viewport while history appeared above it — both visible simultaneously, creating an overlay/stacking effect. `renderScrolled` was filling the remainder of the viewport with the **bottom** rows of the live screen, which kept the live content pinned. Changed to use the **top** rows instead, so the live screen slides naturally off the bottom as history enters from the top (standard terminal scroll behavior).
- Full session scrollback on reconnect: `CapturePane` now passes `-S -10000` to tmux, seeding the in-process VT emulator with up to 10 000 lines of prior session history on the initial backfill. Previously only the visible screen was captured, so scrollback only covered output since sm4c last started. After a restart, the user can now scroll back through the full prior session history.

- Scrollback overflow: when the scrollback buffer is deeper than the viewport height, `renderScrolled` was emitting more lines than the viewport (e.g. 1 000 lines into a 40-row pane). The excess content overflowed into the sidebar. Fixed by capping `fromScrollback = min(offset, height)` before the loop, so the output is always exactly `height` lines.
- Drag-to-reorder now uses window IDs (stable tmux identifiers like `@3`) as the order key instead of session names. Previously all Claude sessions share the window name `"claude"`, so `applySessionOrder` treated them as the same entry and restored the original order on every tmux poll — making drags revert. Window IDs are unique per window so each session retains its dragged position.
- Drag-to-reorder and click-to-select used incorrect session row heights in `sessionIndexAtY`. `cardBaseStyle` and `sidebarHighlightStyle` both apply `PaddingTop(1)+PaddingBottom(1)`, so each card occupies 3 terminal rows (no cwd) or 4 rows (with cwd). The previous code assumed 1 or 2 rows, causing drag motions to resolve to the wrong session (or −1) and clicks beyond the first two rows of a card to misfire.

### Added

- Drag-to-reorder sidebar sessions. Left-click and drag a session card up or down to change its position in the list. The new order is written atomically to `$XDG_CONFIG_HOME/sm4c/session_order` on mouse release and reapplied on every tmux poll and across restarts, so the order survives quitting and re-entering sm4c. Sessions added after an order was saved (never dragged) append at the end. The drag uses `dragIdx` state on the model — not the terminal-reported held button — so it works on terminals that do not carry the button field in motion events.
- Click to select: left-clicking a sidebar session row moves the highlight to it (same as navigating with `j`/`k`).
- In-process VT scrollback. Mouse-wheel up/down over the right pane scrolls through the emulator's scrollback buffer directly — no tmux copy-mode round-trip. `paneTerminal` grows a `scrollOffset` field and `scroll`/`renderScrolled` methods that combine the tail of the `vt.Scrollback` buffer with the current screen to fill the viewport at the requested offset. Scrolling is instant, works regardless of pane focus state, and is a no-op in alt-screen mode (full-screen apps like claude's TUI manage their own screen). The previous `ScrollPane` / `PaneScroller` seam (which entered tmux copy-mode from the outside) is removed.

### Changed

- Sidebar cwd line now shows only the **basename** of the working directory (e.g. `sm4c` instead of `~/Repos/sm4c`). The home directory itself still displays as `~`. This halves the typical cwd width and avoids path truncation on most sessions. Note: two sessions in different parent directories with the same folder name (e.g. `~/work/api` and `~/personal/api`) will both show `api` — the session name on the first line distinguishes them.
- `handleSessions` preserves the highlighted session by window ID across every poll and reorder. Previously the highlight was an index that silently moved to a different session if a poll or drag changed the list order above the cursor. The cursor now follows the session it was on, not the slot it was in.

### Added

- Mouse wheel scrolling. Scrolling up/down in the sidebar navigates the session list (same as `k`/`j`). Scrolling in pane focus mode forwards SGR wheel-up/down sequences (`\x1b[<64;1;1M` / `\x1b[<65;1;1M`) to the active tmux pane so Claude Code's own scroll behavior works. Note: `WithMouseCellMotion` is now enabled, which means normal terminal text selection requires Shift+drag instead of plain drag.

### Changed

- Right-pane header now shows the Claude Code session title (OSC title, same as the sidebar) instead of the static tmux window name. In pane focus mode the title is highlighted using the chip style instead of appending a separate `[focus]` label — the highlighted name itself serves as the focus indicator. The sidebar-hidden hint (`[ctrl+b: show sidebar]`) is preserved beside the title when zoomed.
- Notification debounce raised from 6 s to 7 s. The `?` glyph was still occasionally appearing after task completions on some machines where the Claude Code notification hook fires slightly after the 6 s window. 7 s provides an extra second of headroom while still leaving the pathway open for genuine "waiting for input" signals that arrive later.

### Added

- Sidebar session names strip Claude Code's animated status icon prefix. Claude Code formats its terminal title as `<icon> <name>` (e.g. `⠋ my-project`) where the icon is a spinner frame, `✓`, or `?`. sm4c already surfaces session status through its own glyph column, so the icon is stripped — only the project/session name is shown. The rule is narrow: only a single non-alphanumeric leading rune followed by a space is removed, so titles that happen to start with punctuation are left untouched.
- Sidebar session names now reflect Claude Code's dynamic terminal title. Claude Code writes its session/project name via OSC 0/2 escape sequences. tmux intercepts and stores these as `#{pane_title}`, which sm4c now includes in the `list-windows` poll format. `renderSessionList` prefers the OSC title over the static tmux window name ("claude") when one is available, so the sidebar shows names like "my-project" — identical to what Ghostty/WezTerm tab titles show.

### Fixed

- Status spinner now works for sessions started via `n` (new session) during a running sm4c instance. The previous `startHookListener` goroutine had no stop mechanism — it ran for the lifetime of the process. On FIFO, reads are exclusive (not broadcast), so when `sm4c n` re-entered `Run` and spawned a second listener on the same FIFO, the two readers split writes non-deterministically. Roughly half of all hook events went to the old (unconsumable) channel and were silently dropped. The listener now returns a stop function backed by `sync.Once`; `Run` defers it so the goroutine exits before the next `Run` iteration begins.
- Hook auto-install is now idempotent against command changes. Previously `installClaudeHooks` detected existing sm4c entries only by the presence of the `SM4C_HOOK_FIFO` marker string, so a stale hook command (e.g. from an older sm4c build) was never replaced — the user had to manually clear `~/.claude/settings.json`. The new `findSm4cEntry` helper returns the array index of the matching entry; if the entry exists but its command differs from the current build, it is replaced in-place. Other tools' entries in the same event array are untouched. A debug log line is emitted when a stale entry is upgraded.
- Status spinner resumes correctly after answering a Claude question. A race existed between the Stop hook (which left `statusTickArmed = true` from the previous animation) and a rapid `UserPromptSubmit` arrival: `scheduleStatusTick` saw the stale `true` value and returned nil, so the new Working state had no ticker to animate. The hookMsg handler now explicitly clears `statusTickArmed` when a Done event fires, so the next Working transition always arms the tick cleanly.
- Spurious `✓ → ?` transition eliminated. Claude Code fires its `Notification` hook ~5 s after every `Stop` event — for both task completions and genuine "waiting for input" questions. The previous code let every Notification override the Done state, producing a confusing ✓ → ? flip after ordinary task completions. Notification is now suppressed for `notificationDebounce` (6 s) after the most recent Stop, which catches the automatic desktop-notification ping. A genuine Notification that arrives after the debounce window (possible in future Claude Code versions with different timing) still transitions to Waiting.
- Spinner no longer appears prematurely on the first keystroke after a ✓. `notePaneKeystroke` clears Done/Waiting to Idle (·) rather than immediately transitioning to Working; the spinner is driven solely by the `UserPromptSubmit` hook. The `statusTickArmed` reset on Done (introduced alongside the original fix) is sufficient to ensure the hook-driven Working transition arms the tick cleanly.
- Cmd+V paste now works correctly inside a focused Claude pane. bubbletea v1.x enables bracketed paste by default: clipboard content arrives as `KeyMsg{Paste: true}` with the rune payload already decoded. sm4c was forwarding the raw bytes without the `\x1b[200~` / `\x1b[201~` markers, so Claude Code's pane treated embedded newlines as prompt submissions rather than literal newlines. The forwarding path now wraps paste content with the standard bracketed paste markers.
- Shift+Enter and other kitty keyboard protocol keys now reach the focused Claude pane on supporting terminals (Ghostty, WezTerm, kitty, Alacritty, iTerm2 with CSI u mode). bubbletea v1.x cannot name these keys and delivers them as its unexported `unknownCSISequenceMsg` type. The `Update` default branch now uses `reflect` to detect any `[]byte`-backed message and forwards the raw bytes to the focused pane, so `\x1b[13;2u` (Shift+Enter) passes through unchanged. Terminals that do not support the kitty keyboard protocol (e.g. macOS Terminal.app) send plain `0x0d` for Shift+Enter; that limitation is in the terminal emulator, not sm4c.

### Added

- `chipStyle(bg, fg string)` function and `Model.chip()` helper in `style.go` / `app.go`. Key-indicator chips in the footer, help overlay, and right-pane header (`[focus]`, `[?]`, `[j/k]`, `[n]`, `[y]`) were rendered with `keyStyle.Reverse(true)`, which produced a "black chip" appearance on terminals where the default foreground and the sidebar highlight colors are not aligned. Chips now use the same `bg`/`fg` indices as the sidebar selection band, making the palette consistent across the entire sidebar column. The now-unused `keyStyle` var was removed.

### Changed

- Sidebar layout: session cards are joined with a **single newline** (no extra blank line between items). Card styles use **PaddingTop/Bottom(1)** plus **PaddingLeft(1)** so the list has a small left inset while the right edge stays flush with the column divider. Session **names** are **Bold** on every row; the highlighted row also applies the configured highlight foreground to the name. The cwd line uses **Faint** on the highlight bar so it stays secondary to the name. Default highlight foreground is **`255`** (xterm white) instead of **`15`** — Bold on the bar targets the name only (earlier Bold+ANSI15 on the whole bar could read as muted blue-gray on some terminals). **cardPaddingW** is **1** to match the left inset for path truncation.

### Added

- Config: `sidebar_highlight_bg` and `sidebar_highlight_fg` accept decimal indices **`"0"`**–**`"255"`** — ANSI **0–15** plus the **xterm 256-color** palette **16–255**. `tui.Run` calls **`lipgloss.SetDefaultRenderer(lipgloss.NewRenderer(out))`** so termenv probes the real output stream and lipgloss maps indices to the terminal's color profile (256-color sequences when supported, otherwise down-mapped to the nearest ANSI color). Empty string still means built-in defaults.

### Changed

- Default sidebar selection colors reverted from blue (**`4`**) to gray (**`8`**) + bright white (**`15`**); live feedback preferred the neutral bar over the blue default. The cwd line still uses the same foreground index with `Faint`. Status glyphs on the highlighted row still use `statusGlyphPlain` so nested lipgloss does not fight the bar colors.

### Fixed

- M3e polish (round 3): "typing lands at the bottom of the pane" reappears when switching to a session whose tmux cached dims already match the sm4c viewport. `resizeHighlightedWindow` now detects the first-ever resize for each window and takes the wiggle path (W,H+1 → W,H) on that visit so tmux is guaranteed to SIGWINCH claude even when the matching-dim `resize-window` would have been a no-op. Subsequent resizes for the same window at the same dims stay debounced, so the fix costs exactly one extra `resize-window` round-trip per window per TUI lifetime. The earlier handleWindowClosed-driven wiggle is preserved untouched — the two arms together cover the "new window" and "post-close survivor" failure modes of the same underlying tmux quirk. Two tests updated/added: `TestWindowSizeEmitsResizeForHighlightedWindow` now expects the wiggle shape on startup, and the new `TestFirstResizePerWindowWiggles` asserts the first visit to EACH window wiggles while later visits debounce.

### Changed

- M3e polish (round 3): session-card chrome reverted to a flat full-width selection band. The round-2 rounded border (`lipgloss.RoundedBorder`, `╭╮╰╯`) showed two problems in live use — the ANSI-8 background color stopped at the border interior and left a visible ring of unpainted terminal background between the text and the outline, and the border's 2-col outer width vs. the base card's 0-col frame made the list visibly jump horizontally as the cursor moved across sessions. Both card variants now share only `Padding(0, 1)` with no border or margin, so the only visible difference between a selected and unselected row is the ANSI-8 background fill — matching the "solid filled bar" shape the user asked for and the one claude-squad uses. Tests `TestSessionCardHighlightHasNoBorder` and `TestSessionCardsShareOuterWidth` pin the new contract.

### Added

- M3e polish: sidebar zoom (`z`). Pressing `z` while focus is on the sidebar collapses the sidebar column entirely and hands the whole viewport to the right pane — the same "give claude the full screen" gesture tmux calls zoom. The flip is atomic: `sidebarHidden = true` and `focus = FocusPane` both take effect in the same Update tick, plus the pane viewport is re-measured (via `rightPaneBodyDims`' new sidebar-hidden branch) and tmux is issued a resize-window so claude redraws for the new grid. The restoration path stays on the existing `ctrl+b` binding — from pane focus, `ctrl+b` now un-hides the sidebar and pulls focus back at the same time. Single-binding symmetry: users already know `ctrl+b` means "back to sidebar"; in zoom mode that verb just also means "show it again". The right-pane header grows a one-time hint (`[ctrl+b: show sidebar]`) while zoomed so first-time users are not stranded. We deliberately chose `z` over the requested `Ctrl+Shift+B` after confirming that most terminals (anything without the Kitty keyboard protocol enabled) collapse `Ctrl+Shift+B` to the same byte as `Ctrl+B`, so bubbletea cannot disambiguate them; `z` is the tmux-zoom convention and only takes effect in sidebar focus, so it does not steal keystrokes from claude.
- M3e polish: session-card layout in the sidebar. Each session now renders as a two-line card — `<glyph> <name>` on the first line and a faint `<short-cwd>` on the second — instead of a single name row. The cwd is tmux's `#{pane_current_path}` on the active pane (sanitized via `safe.Line`), shortened to `~/…` when it lives under the user's home directory and truncated from the head with `…` when it would overflow the sidebar column. Cards are separated by a blank line so the list reads as discrete items, matching the claude-squad / Cursor "group by repo" convention that live feedback asked for. When `Session.Cwd` is empty (tmux has not yet resolved a path, e.g. pane process mid-exit, or the test stub does not set it) the second line is omitted cleanly so no blank-indent row leaks into the view.
- M3e polish: card-style highlight. The highlighted row is now padded with a `lipgloss.Width(sidebarContentW)` before the `Reverse(true)` attribute is applied, so the selection reads as a visible band spanning the entire sidebar column instead of a reverse-video run that ended at the glyph text. Matches the feedback screenshot from claude-squad, where the selected session is a clear "card" the eye picks out from across the room. Unit-test paths that never emit a `WindowSizeMsg` (and therefore have no known content width) fall back to the pre-M3e single-run highlight, so every existing substring-based assertion about highlighted rows still passes.
- M3e polish: `tmuxctl.Window.CurrentPath` — new field populated from `#{pane_current_path}` in the `list-windows` format string. Placed second-to-last in the wire format so `window_name` stays the trailing free-form slot that absorbs any leftover tabs; on the vanishingly rare path containing a tab, `safe.Line` strips the embedded control byte and the tail shifts into the name slot without crashing the parser. `tui.Session.Cwd` mirrors the new field through the CLI adapter in `cmd/sm4c/cli/tui.go`, and `parseWindows` is updated from `SplitN=6` to `SplitN=7` with matching coverage in `TestParseWindows_Basic`, `TestParseWindows_EmptyCurrentPath` (new), `TestParseWindows_SanitizesName`, and `TestParseWindows_NameWithTabs`.

### Changed

- M3d polish: Attention glyph is no longer rendered in bold. The shape (`✓`) already carries the "done, your turn" signal — bold was adding weight that over-indexed the signal against the Working spinner and the Idle dot, which are both rendered in the sidebar's native weight. The progression (`●` → `!` → bold `✓` → `✓`) reflects a deliberate de-escalation: every iteration made the signal quieter while keeping it unambiguous. Regular weight lets every sidebar row look visually equal — no session shouts louder than any other, and the checkmark shape is the thing that tells the user "this one wants you." `attentionStyle` is now the identity style (`lipgloss.NewStyle()`); the only color-bearing sidebar attribute is the `Reverse(true)` on the highlighted row, which the shape-based signal survives unchanged. Matching doc-comment / README / `doc.go` revisions.
- M3d polish: right-pane header no longer shows the window ID (`@N`). Same rationale as the sidebar row cleanup — the tmux ID is an opaque identifier users never refer to by hand, and live usage found it stole horizontal space in the header without ever being read. `sm4c ls` still surfaces IDs for debugging. The `[focus]` / `[ctrl+b to focus]` indicator now sits directly after the session name, which is the only user-meaningful label in that slot.
- M3d polish: sidebar layout restructure. The always-visible "key bar" that listed every binding under the session list is gone. In its place, the sidebar grows a single "? help" hint anchored at the bottom of the column, and pressing `?` toggles an expanded block of every binding for the current focus — also anchored at the bottom. The close-confirmation prompt (`close <name>? y …`) replaces the hint while a kill is armed so the user sees exactly one question at a time. Rationale: live usage found the permanent key bar stole vertical space from the session list and that users who wanted the full table reached for `?` anyway. Hiding the list behind `?` preserves discovery ("press this one visible key to see everything") without the permanent vertical cost. `renderSidebarColumn` splits into a top block (header, session list, optional fetch-error line) and a bottom block (close prompt ∣ expanded help ∣ compact hint) with lipgloss height math between them to pin the bottom block to the actual bottom of the viewport. The obsolete `renderKeys` helper is deleted and the affected app-level tests (`TestViewEmptyStateRendersSidebarChrome`, `TestViewRendersSidebarWhenSessionsPresent`, `TestViewHelpSectionOnlyWhenToggled`) are tightened to pin the new invariants — default render hides every non-`?` binding, `?` reveals the full list, and `?` toggles round-trip to the hint.
- M3d polish: Attention glyph swapped from bold-red `!` to bold `✓` (U+2713 CHECK MARK). Live usage surfaced that red-bang read as "error / something broke" when the actual state semantic is the opposite — claude finished a task successfully and is handing control back. A checkmark reads as "done, your turn" without the alarm connotation, and the shape is still unmistakably different from the round dots (`·`, `●`) used for Quiet/Idle and the braille spinner used for Working, so the "needs you" signal still carries through the reverse-video attribute on highlighted rows. Color-wise, the glyph is now rendered bold on the user's native foreground rather than in ANSI red — the semantic no longer calls for a warning color. Shape carries the signal; bold reinforces without implying failure.
- M3d polish: `monitor_silence` default dropped from 3s to 1.5s. Live usage showed 3s read as sluggish — users saw claude's final token land and then waited a visible beat before the sidebar caught up, and for short prompts the "done" cue often arrived AFTER the user had already started typing their next message. 1.5s is short enough to feel reactive but still longer than claude's thinking-indicator update cadence (~1s between frames), so mid-response pauses don't prematurely flip the glyph. Users who want even faster reactions can drop to `"1s"` in `config.toml` at the cost of occasional flicker on slow tool calls.
- M3d polish: Attention is now layered on top of silence instead of competing with Working. Live usage showed the bang appearing too soon — claude rings the bell at several points inside a single response (tool-call boundaries, partial confirmations, completion), and the previous FSM surfaced each one immediately as `!`, yanking the spinner away mid-stream and telling the user "done" while claude was still generating. The new rule is: a bell byte sets `paneStatus.bell = true` and is REMEMBERED, but the glyph does not flip to Attention while bytes are still flowing. Working keeps the spinner animating through mid-response bells; only once the pane goes silent for `monitor_silence` (default 3s) does the remembered bell surface as Attention (`!`). If no bell rang during the run, silence still produces Idle (`●`) as before. The priority order is now: echo suppression wins (user is typing → Idle) → never-had-output → actively emitting → Working → silent + bell → Attention → silent, no bell → Idle. Matching arc changes in `derivedStatus`, the package-level state-diagram comment in `status.go`, `doc.go`, and the README "Session status glyphs" section. `TestDerivedStatusTransitions` gains "bell during Working stays Working" and flips the old "bell still wins over recent keystroke" case to "recent keystroke suppresses pending bell" (the user's hands are already on the pane; flashing the bang is noise). The zero-threshold opt-out case now documents that bell is never surfaced either, since "silent" never becomes true in that mode.
- M3d polish: Attention glyph swapped from red `●` to red `!`. Live usage surfaced that rowHighlightStyle's `Reverse(true)` (which paints the selected sidebar row in reverse video) swaps foreground and background at render time, pushing the attention red into the *background* channel and leaving the dot itself drawn in the default foreground — users saw "the color around the dot changes, not the dot itself". Switching to a shape-distinct glyph (`!`) means the attention signal survives the fg/bg swap: even if reverse video wins the color argument on the highlighted row, the bang is still unmistakably different from the round dots (`·`, `●`) used for Quiet/Idle and the braille spinner used for Working. Red + bold stays on as reinforcement for terminals where the color does carry through.
- M3d polish: `keystrokeEchoWindow` reduced from 1500ms to 400ms. Live usage surfaced that 1.5s swallowed most of claude's short responses — prompts that finished within a second of Enter spent their entire lifetime inside the suppression window, so the spinner "never moved". 400ms is still much longer than a keypress echo (tens of milliseconds locally, rarely over 200ms even over SSH) while small enough that almost all real claude activity lands outside it. The right mental model is "echo is near-instant; claude is seconds-scale", and 400ms sits firmly in the gap.
- M3d polish: sidebar row format simplified from `<glyph> <name> <window-id>` to `<glyph> <name>`. Window IDs are opaque tmux identifiers (`@3`) that users never refer to by hand — they were pure noise stealing horizontal space on narrow sidebars, and live usage confirmed nobody was actually reading them. `sm4c ls` still surfaces IDs for debugging.
- M3d polish: Attention glyph color swapped from ANSI yellow (`Color("3")`) to ANSI red (`Color("1")`). The original choice was "amber is softer than red," but yellow resolves to pure-yellow rather than amber on a surprising number of terminal themes, at which point it reads as "informational" and loses the alerting semantic entirely. Red is the universal "needs you" color across every mainstream theme (Solarized, Gruvbox, Iceberg, GitHub Dark, Apple defaults, Nord, Dracula…), which is the signal we actually want. Hex colors are still forbidden by the CI gate; color 1 is the best 0-15 match to the intent.

### Fixed

- M3d: typed characters still landed at the bottom of the surviving session's preview after closing another session (`x` + `y`), even with the sizedFor cache cleared on close. The residual bug was one layer deeper: clearing `sizedFor` forces `resizeHighlightedWindow` to EMIT a resize-window call, but tmux no-ops a resize-window whose target dims match the pane's current dims — and after a close the surviving pane's current dims usually DO match our `paneViewW`/`paneViewH` already, because the emulator column did not change size when another window disappeared. No actual tmux resize happens, no SIGWINCH reaches claude, claude does not redraw, and the emulator's cursor stays parked at the bottom-ish row left by the pre-close `capture-pane -p -e` backfill (capture output does not include a cursor-repositioning escape at the end). Subsequent character echoes from claude — which assume claude's own drawing code has already positioned the cursor to the input box row — then land wherever the stale cursor is. The fix introduces a new `Model.forceResizePending` one-shot flag that `handleWindowClosed` arms; the next `resizeHighlightedWindow` call consumes it and issues a "wiggle" through a new `forceResizeManagedWindow` helper: resize to `(W, H+1)` first, then immediately back to `(W, H)`. Both calls are tmux no-op-proof (the first changes height by 1, the second changes it back), so SIGWINCH is guaranteed to fire on the survivor and claude is guaranteed to redraw its UI from scratch — which includes the cursor-repositioning escapes that re-sync the emulator. Backfill flow is "capture first, then live": when a pane resolves for the first time, the Model sets `paneCapturing[paneID] = true` and emits a capture cmd; any `paneDataMsg` for that pane arriving mid-capture is queued in a bounded `panePending` buffer (64 KiB cap, tail-drop on overflow) instead of written to the emulator; on `paneCaptureMsg`, the handler mints the emulator (if missing), writes the captured bytes, flushes pending in order, and marks `paneCaptured[paneID] = true` so a second attempt never fires — even on capture error, pending is still flushed so the user never loses live data to a soft failure. Viewport sync is choke-pointed through `resizeHighlightedWindow`, called from `WindowSizeMsg` (when body dims actually change), from the `sessionsMsg` tail (so initial-highlight snap also sizes the target), and from `j`/`k` (so cursor-driven focus changes propagate); a `sizedFor` map debounces duplicate `(wid, w, h)` triples, and stale entries are pruned when `handleSessions` drops their window. New tests cover: first-resolve emits a capture cmd; same-pane re-resolve does not; live bytes are buffered during capture; capture+pending flush in the correct order; capture error still flushes pending and still marks captured; pending buffer is bounded; same-size `WindowSizeMsg` debounces; highlight change emits exactly one resize for the new window; flicking back to an already-sized window does not re-resize; `sizedFor` is pruned on session close. `cmd/sm4c/cli/tui.go` wires both new seams from the shared `tmuxctl.OneShot` and keeps them live even when the control-mode bridge declines to spawn.

### Fixed

- M3c: right-pane "staircase" distortion after entering the TUI. `tmux capture-pane -p -e` emits bare `\n` row terminators, which the `charmbracelet/x/vt` emulator — correctly, per VT — parsed as "advance one row, keep column," producing a descending staircase of indented rows that the user could only clear with a manual terminal resize. `internal/tui/panes.go` now normalizes bare `\n` to `\r\n` in captured data (live `%output` bytes already use CRLF and are left alone), and `internal/tui/app.go`'s `handlePaneCapture` runs every capture-pane payload through the helper before writing it to the emulator. New tests cover bare-LF conversion, preservation of existing CRLF, and the no-op fast path.
- M3c: TUI freeze on new-session entry. The VT emulator answers terminal queries (CSI c, CSI >0q, XTVERSION) by queuing response bytes into an internal buffer exposed via `Read`; when nothing drained that buffer, the pipe filled and the next `emu.Write` call deadlocked the entire Bubble Tea loop — invisible to `Update`, invisible to key handling, just a frozen screen. `newPaneTerminal` now starts a background goroutine that drains `emu.Read` into `io.Discard` for the emulator's lifetime. The responses are correctly discarded because tmux already answered claude's queries on the real pane PTY — our emulator is a passive observer, not the terminal claude is attached to, so its generated responses have no correct destination.
- M3c: ghost content at the top of freshly-spawned session previews. The CLI-spawn → re-enter-TUI loop captured the pane while claude was still booting; the captured screen was a half-baked render that claude's subsequent steady-state redrawing wrote over partially (most TUIs redraw via cursor-positioned writes, not `CSI 2J`), leaving stray anchored-at-bottom content until the user jiggled the terminal. The Model now exposes a `skipCaptureWindow` field (seeded from `Deps.InitialHighlight`) so the first pane-resolve for a freshly-spawned window skips the `capture-pane` backfill entirely; live `%output` paints the emulator from a clean slate within ~1 claude frame. Existing sessions the user navigates to mid-TUI-session are unaffected. New `TestInitialHighlightWindowSkipsFirstCapture` pins the selective opt-out.
- M3c: preview "disconnected" right after TUI startup. The control-mode `tmuxctl.Client` was launched via `exec.CommandContext` tied to the startup context, so when `setupPaneBridge` returned, `defer cancelStart()` killed the tmux subprocess and closed the event channel before the Model could consume a single `%output` notification. Switched to `exec.Command` with explicit `Close()`-driven shutdown so the subprocess lifetime is tied to the TUI program, not to startup.
- M3c: sidebar never reflected the session name passed via `claude -n <name>`. Claude does not reliably emit a rename escape sequence on startup, so tmux's window name stayed at the shell default. `spawn.go` now parses `-n` / `--name` from the claude argv (`nameFromClaudeArgs`) and pre-seeds the tmux window name via the `new-window -n` / `new-session -n` flag at creation time; the sidebar reads `#{window_name}` as before and so picks up the label on the very first list-windows poll.
- M3c: surviving session preview garbled after closing another session. Tmux's "kill active window" switches the control client to the next window of the session, and that switch can dribble a partial redraw (cursor-positioned row rewrites without a `CSI 2J`) into the `%output` stream which then lands on top of the surviving pane's pre-close emulator state — producing a "mostly-right but with stale rows peeking through the gaps" view that only a manual resize could clean up. `handleWindowClosed` now invalidates every surviving pane's capture state (paneByWindow, paneTerminals, paneCaptured, paneCapturing, panePending) and clears `resolvedWindowID` so the `fetchSessions` round-trip immediately following the close naturally triggers a re-resolve + re-capture for the newly-highlighted survivor. The fresh capture-pane snapshot paints over the mixed state in one shot. New `TestWindowClosedMsgInvalidatesSurvivorPanes` pins the survivor-invalidation contract.

### Changed

- M3c: cleaned up debug-log scaffolding in `internal/tui/app.go`, `internal/tui/panes.go`, and `cmd/sm4c/cli/tui.go`. The `SM4C_DEBUG_LOG` facility in `debuglog.go` stays (zero cost when unset, invaluable for the next bug), but the per-render, per-keystroke, and per-emulator-write call sites that flooded the trace file during the freeze/distortion investigations are gone. Kept: Start OK/FAIL, bridge exit, backpressure drops, session-poll counts, pane resolve / capture / data chunk sizes. Removed: View start/end, renderSidebarView / renderRightPane step logs, handleKey per-focus dispatch traces, emu.Write / emu.Render start/end pairs, and the unused `previewBytes` helper.
- M3a-refinement: sm4c no longer exec-attaches into tmux from any code path. `sm4c [claude-args…]` still spawns a tagged claude window on the sm4c socket, but instead of handing the terminal to a raw `tmux attach-session` it opens the TUI focused on the freshly-spawned session (new `initialHighlight` hint threaded through `tui.Run` / `NewModel`). The TUI's `Enter` binding is now a deliberate no-op reserved for M3c's focus shortcut; there is no keystroke, CLI flag, or Action that drops the user into a bare tmux session. Rationale: the whole premise of sm4c is "one surface for concurrent claude sessions." If a user wants a raw `tmux attach`, they can use tmux directly. The `ActionAttachSession` intent, `Model.SelectedWindowID()`, `execAttach`/`execAttachReal`, `syscall.Exec`, and the old `spawnAndAttach` helper are all removed; `runTUI` and `runLaunch` funnel through a shared `openTUI` that runs the TUI in a re-entry loop — `n` (new session) now spawns a window outside the TUI and re-enters with that window as initial highlight, so the sidebar briefly blinks and redraws with the new row pre-selected rather than kicking the user out to tmux. Tests covering the old attach exec path (`TestTUIAttachActionExecsCorrectWindow`, `TestEnterOnHighlightedSessionEmitsAttachIntent`) are replaced with pins on the new behavior: Enter is inert, the initial-highlight hint snaps to matching sessions on first fetch, and the hint is retained across polls until a matching row appears (so a tmux indexing lag can't lose the target).
