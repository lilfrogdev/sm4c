## [Unreleased]

### Added

- M3d: `internal/tui` — animated per-session status glyphs in the sidebar. Each row leads with a two-column cell that reflects that session's live state, derived from the `%output` byte stream the control-mode bridge already forwards (no tmux `monitor-bell` / `monitor-activity` / `monitor-silence` options are toggled — those flags are sticky on tmux's side and fit the "notify me about windows I'm not looking at" use case, not sm4c's reactive UI). The FSM is: `Quiet` (never emitted a byte; faint `·`) → `Working` (emitting bytes now; animated 10-frame braille spinner `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` at 100ms/frame for a ~1s clockwise rotation) → `Idle` (emitted bytes, then silent for ≥ `monitor_silence`; solid `●`) → `Working` again, with `Attention` (pane emitted a BEL byte; amber `●`, ANSI yellow) overriding all three until the user sends a keystroke to that pane (at which point the flag clears, since the user has clearly noticed). Braille Patterns (U+2800..U+28FF) renders as a single fixed-width cell in every terminal sm4c targets on macOS/Linux in 2026, so the two-cell status column never jitters; the frame set is stored as `[]string` (not a `string`) because each codepoint is three UTF-8 bytes and byte-indexing would slice them apart. The animation ticker self-gates: it only runs while at least one pane is `Working`, so an all-idle TUI is silent. `paneStatuses` is keyed by window ID (not pane ID) so a close-session churn on `paneByWindow` cannot flicker the sidebar to Quiet for surviving sessions; a companion `paneToWindow` reverse map lets `%output` arrivals find their owning window in one lookup. New `Deps.SilenceThreshold` plumbs `Config.MonitorSilence` (default bumped from 5s to 3s — 3s matched the "claude just finished answering, I'm ready to react" feel during live testing) through `openTUI` → `runTUIProgramReal` → `tui.NewModel`. Unit tests cover every FSM arrow, BEL detection, ticker self-gating by state, frame advancement on tick, stop-when-idle, ticker arm on first byte, attention clear on keystroke, render round-trips for each state, and the boundary of the silence threshold. ANSI colors only (lipgloss `Color("3")` for amber — closest 0-15 match to Cursor's orange attention dot — rejected for hex via the existing CI gate).

- M3a: `internal/tui` — sidebar view, present at all times, rendered as a visually distinct left column. On terminals >= 60 cols wide, the sidebar sits in a bordered left column (width scales to roughly one-third of viewport, clamped to [24, 40]) joined horizontally to a right-pane placeholder ("no active session" / "selected: ") that M3b will replace with the VT-rendered hosted claude pane. Narrower terminals fall back to a stacked layout so content doesn't get squeezed. `tea.WindowSizeMsg` is captured into Model state so the split geometry tracks live resizes. A single unified layout renders the title, session list, key bar, and (empty-state only) disclaimer footer; the sidebar never collapses to a bare header or disappears when no sessions are live. With zero sessions, the list area shows a faint "no sessions yet — press n to start one" placeholder inline; with one or more sessions it lists them one per row with an active-marker column, name column, and faint window-id column. A new `tui.SessionLister` dependency (wired by `cmd/sm4c/cli/tui.go` to `tmuxctl.OneShot.ListWindows`, filtered to `Managed()` windows) feeds the Model via Bubble Tea `tea.Cmd` fetches on a serial fetch→tick→fetch loop at a `DefaultPollInterval` of 1s. Key bindings grew to `j` / `k` / `↑` / `↓` (navigate highlight, no-wrap), `Enter` (commit `ActionAttachSession` with the highlighted window's ID), and `Ctrl+B` (reserved no-op placeholder for M3b's focus toggle). The sidebar header pluralizes the session count, an active-marker column flags tmux's current window, and fetch errors surface as a faint one-liner without blanking stale data. The runtime now uses `tea.WithAltScreen` so live repaints do not pollute scrollback. `cmd/sm4c/cli/tui.go` gained an `ActionAttachSession` branch that `execAttach`es into `tmux attach-session` for the reported window; `interactiveStdin` is now a package-level seam so CLI integration tests can exercise the full dispatch without a real TTY. Tests cover session-list clamping on insertions/deletions, j/k boundary behavior, Enter on empty state (no-op), Enter with a selection (correct Action + window ID), `Ctrl+B` staying inert, tick → fetch chaining, disclaimer-footer scoping, and all sidebar substrings (name, window ID, pluralized count, bindings). CLI test `TestTUIAttachActionExecsCorrectWindow` drives a real `tui.Model` through its public API and asserts the resulting tmux argv references the correct window. Embedded pane rendering, input routing, status badges, and the compose flow remain deferred to M3b–M3e.
- M3b.1: `internal/tui` — read-only raw-bytes pane preview. The right column is no longer a static "selected" placeholder; when the CLI has set up the control-mode bridge, it streams live bytes from the highlighted session's active tmux pane and renders the latest N lines as printable-ASCII text clipped to the column's dimensions. A per-pane ring buffer (`paneBufferBytes` = 8 KiB) keeps the tail of each pane's output; a fresh snapshot is taken on every render so older bytes scroll off the top. Every non-displayable state has an explicit rendering: "no active session", "pane preview unavailable" (no stream/resolver), "preview disconnected" (channel closed), "resolving pane…", "pane lookup failed: ", "waiting for output ". `stripToPrintable` drops all non-printable bytes (ANSI escapes, C0/C1 controls, non-ASCII) so nothing the remote pane emits can corrupt the outer terminal while the full VT emulator is pending in M3b.2. Two new dependency seams — `tui.PaneEventStream` (a factory returning a `<-chan PaneEvent` of `{PaneID, Data}`) and `tui.ActivePaneResolver` (a `ctx, windowID -> paneID` function) — let the TUI consume tmux without ever importing `tmuxctl`. Both are optional: a nil stream/resolver keeps every empty-state and unit test inert, and the right pane shows the "unavailable" hint. Navigation keys (`j`/`k`/`↑`/`↓`) debounce resolver calls so a cached window is not re-queried, and a failed resolve is stored per-window so one broken session does not blank working previews for the rest. `Model.handleSessions` prunes `paneByWindow`/`paneErrByWindow` entries when their windows close.
- M3b.1: `internal/tmuxctl` — `OneShot.ActivePane(ctx, windowID)` returns the `%<digits>` pane ID of a window's active pane via `display-message -p -F '#{pane_id}'`, mapping a missing server or window to a new `ErrNoSuchPane` sentinel so callers can treat soft failures distinctly from fatal errors. `parsePaneID` enforces the `%`+digits shape with at least one digit. `Client.Start` drops `-D` from its `new-session` invocation: multiple sm4c processes (a long-lived TUI plus a one-shot `sm4c ls` in another terminal, say) now coexist on the socket without detaching each other mid-session. `internal/tmuxctl/oneshot_integration_test.go` gains `TestIntegration_OneShot_ActivePane` which pins the end-to-end `display-message` round-trip, including the missing-window failure mode.
- M3b.1: `cmd/sm4c/cli/tui.go` — new `setupPaneBridge` stands up a long-lived `tmuxctl.Client` in control mode and a goroutine that filters its `%output` notifications into a `tui.PaneEvent` channel with a 512-slot bounded queue and drop-on-overflow backpressure. The bridge is strictly optional: if no sm4c session exists yet (fresh install), or `Client.Start` errors/times out (3s bound), the TUI launches with nil stream/resolver and the right pane shows the "unavailable" hint rather than crashing. `Client.Close` is chained so the bridge goroutine exits on TUI teardown, which closes the channel, which emits `paneStreamClosedMsg` into the Model and halts its re-arm loop.
- M3b.2: `internal/tui` — the right-pane preview now runs through a `github.com/charmbracelet/x/vt` emulator, so colors, cursor motion, line wrapping, and screen clears render identically to a native tmux attach within the column. A `paneTerminal` type pairs a `vt.Emulator` with a "has received any bytes yet" flag (so the "waiting for output" hint stays visible before the first chunk), replaces the M3b.1 ring buffer, and is keyed by pane ID the same way. `handlePaneData` writes chunks into the emulator (the parser absorbs partial escape sequences across chunk boundaries, so `%output` splits are safe), and `View` emits the emulator's `Render()` — which re-encodes SGR escapes — directly, inheriting the user's native terminal palette without any hex-color policy work. The old `stripToPrintable` / `clipLine` helpers and the `paneBufferBytes` ring are gone: the emulator parses every control sequence the pane emits, so a stray OSC / APC / DCS from claude cannot corrupt the outer terminal. Terminal resize (`tea.WindowSizeMsg`) now recomputes the right-pane body geometry (`rightPaneBodyDims`) and `Resize`s every live emulator to match, so wrapping does not drift when the user grows or shrinks their window. Unit tests exercise write+render round-trips (empty, plain bytes, ANSI consumed not echoed, split-escape chunks, resize, styled output), per-pane isolation, control-sequence absorption end-to-end, emulator sizing across resizes, and all the pre-existing state-machine pins (stream-closed, resolver-error surfacing, pane pruning). `preview_test.go` now seeds the model with a `WindowSizeMsg` before feeding `\r\n`-terminated pane bytes so the on-demand emulator is sized to the visible column.
- M3b.3: `internal/tmuxctl` — two new one-shots finish the pane-preview backend. `OneShot.CapturePane(ctx, paneID)` runs `tmux capture-pane -p -e -t %N` and returns the visible screen with ANSI escapes preserved (`-e`); missing server / missing pane map to the existing `ErrNoSuchPane` sentinel. `OneShot.ResizeWindow(ctx, windowID, W, H)` runs `tmux resize-window -t @N -x W -y H` and maps missing server / missing window to a new `ErrNoSuchWindow` sentinel. Both inputs are shape-validated (`%`+digits, `@`+digits) before reaching tmux, non-positive dims are rejected up front, and argv never touches a shell. New integration tests exercise both one-shots end-to-end: `TestIntegration_OneShot_CapturePane` prints a sentinel into a real pane and polls until capture sees it; `TestIntegration_OneShot_ResizeWindow` asserts the window's reported size changes to the requested grid and that the helper rejects non-positive dims / missing windows cleanly. (We explored pinning `window-size manual` on the sm4c session to pre-empt tmux's automatic resize behavior, but on tmux 3.6a that option reliably tears down a detached-only server — the steady state for sm4c, which never attaches — with "server exited unexpectedly". Direct `resize-window` calls already stick with the default `window-size latest` for both standalone and control-mode-attached servers, so we don't pin the option; if the auto-resize behavior ever bites us in a live session, we'll revisit with a per-session scope.)
- M3c: `internal/tmuxctl` — `OneShot.SendKeys(ctx, paneID, data)` forwards raw input bytes into a tmux pane via `send-keys -t %N -H <hex>`. Bytes are hex-encoded (two lowercase digits per byte) so argv never carries a literal control byte, newline, shell meta, or UTF-8 continuation — `send-keys -H` on the tmux side decodes them back before writing to the pane's PTY, which means the full keystroke wire (UTF-8 runes, C0 controls, CSI sequences, Alt prefixes) passes through with byte-identical fidelity and no shell / tmux parser ever sees the payload as text. Pane ID must match the `%`+digits shape; payload is bounded at 4 KiB per call; empty payloads are a no-op success. Missing server / missing pane map to the existing `ErrNoSuchPane` sentinel so the TUI can demote a dead pane back to read-only without crashing. New unit test `TestHexByte` pins the 256-byte encoding exhaustively; new integration test `TestIntegration_OneShot_SendKeys` asserts round-trip through a real `cat` pane (sentinel + newline in, sentinel observed in capture output) plus the missing-pane, malformed-id, empty, and oversize-rejection failure modes.
- M3c: `internal/tui` — focus state + input routing. The Model grows a `Focus` enum (`FocusSidebar` / `FocusPane`), a `Deps.InitialFocus` seam, and a `Deps.KeySender` seam that lets the TUI forward keystrokes without importing `tmuxctl`. `Ctrl+B` is now the universal focus toggle: from the sidebar it moves focus into the highlighted session's pane (if any), from the pane it moves focus back to the sidebar. `Enter` on a highlighted sidebar row is a shortcut for `Ctrl+B` — it moves focus into the pane instead of being inert. In sidebar focus, `sm4c` keeps its own bindings (`j`/`k`/`↑`/`↓`, `n`, `?`, `q`, `Ctrl+C`). In pane focus, every keystroke is translated to its terminal byte sequence by a new `keyMsgToBytes` table (UTF-8 runes, C0 controls incl. `Ctrl+A`..`Ctrl+Z`, Enter→`\r`, Tab→`\t`, Backspace→`0x7F`, Escape→`0x1B`, Space, arrow keys as CSI, Home/End/PgUp/PgDn/Delete/Shift-Tab as CSI, Ctrl+arrow/Home/End/PgUp/PgDn as CSI with modifier `;5`, F1–F4 as SS3, F5–F12 as CSI, Alt prefix as `0x1B`) and sent via `KeySender`; `Ctrl+C` in pane focus is forwarded to claude (interrupts the running turn), while `Ctrl+C` in sidebar focus still quits sm4c. Unresolved or unknown keys are dropped on the floor rather than leaking out. If the pane disappears mid-turn (`tui.ErrPaneGone`), the Model reverts focus to the sidebar automatically; other send errors are absorbed silently so a transient tmux hiccup doesn't yank the user around. A visual focus indicator — `[focus]` when in pane focus, `[ctrl+b to focus]` otherwise — renders in the right-pane header so the user always knows where keystrokes will land. Startup focus is context-aware: bare `sm4c` starts on the sidebar (there's no session to type into yet); `sm4c [claude-args…]` and the `n` re-entry both start on the pane so the user can type into the freshly-spawned session immediately. Quitting (`q` / `Ctrl+C` from the sidebar) leaves claude sessions running on the sm4c tmux socket so the user can rejoin by re-running `sm4c`.
- M3c: `cmd/sm4c/cli/tui.go` / `launch.go` — wires the `KeySender` seam from `tmuxctl.OneShot.SendKeys` (with `tmuxctl.ErrNoSuchPane` mapped to `tui.ErrPaneGone()` so the Model's focus-revert logic fires), threads `InitialFocus` through `openTUI` / `runTUIProgramReal`, and sets `InitialFocus = FocusPane` on the launch path and on every `n` re-entry while keeping `InitialFocus = FocusSidebar` for the bare-`sm4c` entry. Test `TestRunTUIPassesEmptyInitialHighlight` now also pins that bare `sm4c` lands on the sidebar.
- M3c: tests — new `internal/tui/keys_test.go` covers the rune / control / named-key / Alt-prefix / unmapped-key branches of `keyMsgToBytes`; new `internal/tui/focus_test.go` covers the focus toggle, Enter-to-pane behavior, rune / Enter / Ctrl+C forwarding, Ctrl+C quit semantics by focus, initial focus precedence, pane-gone focus revert, transient-error focus preservation, highlight-gone focus revert, and the read-only-without-KeySender graceful degradation.
- M3c: close-session UX. The sidebar grows an `x` binding that arms the highlighted session for close and, on a follow-up `y` / `Y`, calls a new `tui.WindowCloser` seam (wired from `tmuxctl.OneShot.KillWindow`) to terminate the underlying tmux window. Any non-`y` key cancels the pending close without side effects, so a mis-typed `x` is a safe one-step rollback. While a close is armed, the compact key bar is replaced by a `close <name>? y (any other key cancels)` hint so the user can verify the target before committing. After a successful close the Model prunes its per-pane caches for the departed window and triggers an immediate `sessionsMsg` refresh so the sidebar row disappears without waiting for the next poll tick; a stale pending close (target closed externally mid-confirmation) is cleared on the next poll. `tmuxctl.OneShot.KillWindow` is the public, input-validating counterpart to the existing `killWindow` (restricted to `@<digits>` IDs, server-missing folded into `ErrNoSuchWindow`, shell never consulted), and its CLI-layer adapter folds `ErrNoSuchWindow` into nil so the "already gone" case is treated as a successful close rather than a noisy sidebar error. New `internal/tui/close_test.go` covers arm-without-commit, commit-calls-closer, every cancel branch (n / q / j / esc), no-op without a wired closer, no-op on an empty sidebar, prompt-includes-session-name, closed-msg refreshes sessions, closed-msg prunes pane caches, and stale-pending-close cleanup on an external kill.
- M3c: configurable session-list poll cadence. `config.Config` grows a `session_poll_interval` TOML key (Go duration string: `"1s"`, `"500ms"`, `"2s"`; default 1s) plumbed through `setupOneShot` → `openTUI` → `runTUIProgramReal` into `tui.Deps.PollInterval`. A zero value falls back to the shipped default; a negative value is preserved and treated by the Model as "fetch once, never poll" for snapshot-only environments (CI, smoke tests). `sm4c doctor` now prints the effective `session_poll` cadence alongside the other config echoes. New `TestDefaultSessionPollInterval` pins the 1s default; `TestLoadParsesValidTOML` gains a `session_poll_interval = "2500ms"` case; new `pollinterval_test.go` in `cmd/sm4c/cli` covers the zero → default, positive passthrough, and negative-preserved paths of the CLI-level resolver.
- M3b.3: `internal/tui` — pane-size sync + scrollback backfill completes the M3b pane-preview arc. The Model grows two optional seams: `PaneCapturer` (wraps `tmuxctl.OneShot.CapturePane`) feeds an initial-screen payload into the VT emulator the first time each pane resolves, and `WindowResizer` (wraps `tmuxctl.OneShot.ResizeWindow`) keeps tmux's pane grid in sync with the right-pane body geometry. `NewModel` / `Run` now take a `tui.Deps` struct instead of a 5-argument positional soup, which is the scalable shape as M3c keeps adding dependencies; every field stays nil-safe so unit tests continue to use `Deps{}` / sparse literals. Backfill flow is "capture first, then live": when a pane resolves for the first time, the Model sets `paneCapturing[paneID] = true` and emits a capture cmd; any `paneDataMsg` for that pane arriving mid-capture is queued in a bounded `panePending` buffer (64 KiB cap, tail-drop on overflow) instead of written to the emulator; on `paneCaptureMsg`, the handler mints the emulator (if missing), writes the captured bytes, flushes pending in order, and marks `paneCaptured[paneID] = true` so a second attempt never fires — even on capture error, pending is still flushed so the user never loses live data to a soft failure. Viewport sync is choke-pointed through `resizeHighlightedWindow`, called from `WindowSizeMsg` (when body dims actually change), from the `sessionsMsg` tail (so initial-highlight snap also sizes the target), and from `j`/`k` (so cursor-driven focus changes propagate); a `sizedFor` map debounces duplicate `(wid, w, h)` triples, and stale entries are pruned when `handleSessions` drops their window. New tests cover: first-resolve emits a capture cmd; same-pane re-resolve does not; live bytes are buffered during capture; capture+pending flush in the correct order; capture error still flushes pending and still marks captured; pending buffer is bounded; same-size `WindowSizeMsg` debounces; highlight change emits exactly one resize for the new window; flicking back to an already-sized window does not re-resize; `sizedFor` is pruned on session close. `cmd/sm4c/cli/tui.go` wires both new seams from the shared `tmuxctl.OneShot` and keeps them live even when the control-mode bridge declines to spawn.

### Fixed

- M3c: right-pane "staircase" distortion after entering the TUI. `tmux capture-pane -p -e` emits bare `\n` row terminators, which the `charmbracelet/x/vt` emulator — correctly, per VT — parsed as "advance one row, keep column," producing a descending staircase of indented rows that the user could only clear with a manual terminal resize. `internal/tui/panes.go` now normalizes bare `\n` to `\r\n` in captured data (live `%output` bytes already use CRLF and are left alone), and `internal/tui/app.go`'s `handlePaneCapture` runs every capture-pane payload through the helper before writing it to the emulator. New tests cover bare-LF conversion, preservation of existing CRLF, and the no-op fast path.
- M3c: TUI freeze on new-session entry. The VT emulator answers terminal queries (CSI c, CSI >0q, XTVERSION) by queuing response bytes into an internal buffer exposed via `Read`; when nothing drained that buffer, the pipe filled and the next `emu.Write` call deadlocked the entire Bubble Tea loop — invisible to `Update`, invisible to key handling, just a frozen screen. `newPaneTerminal` now starts a background goroutine that drains `emu.Read` into `io.Discard` for the emulator's lifetime. The responses are correctly discarded because tmux already answered claude's queries on the real pane PTY — our emulator is a passive observer, not the terminal claude is attached to, so its generated responses have no correct destination.
- M3c: ghost content at the top of freshly-spawned session previews. The CLI-spawn → re-enter-TUI loop captured the pane while claude was still booting; the captured screen was a half-baked render that claude's subsequent steady-state redrawing wrote over partially (most TUIs redraw via cursor-positioned writes, not `CSI 2J`), leaving stray anchored-at-bottom content until the user jiggled the terminal. The Model now exposes a `skipCaptureWindow` field (seeded from `Deps.InitialHighlight`) so the first pane-resolve for a freshly-spawned window skips the `capture-pane` backfill entirely; live `%output` paints the emulator from a clean slate within ~1 claude frame. Existing sessions the user navigates to mid-TUI-session are unaffected. New `TestInitialHighlightWindowSkipsFirstCapture` pins the selective opt-out.
- M3c: preview "disconnected" right after TUI startup. The control-mode `tmuxctl.Client` was launched via `exec.CommandContext` tied to the startup context, so when `setupPaneBridge` returned, `defer cancelStart()` killed the tmux subprocess and closed the event channel before the Model could consume a single `%output` notification. Switched to `exec.Command` with explicit `Close()`-driven shutdown so the subprocess lifetime is tied to the TUI program, not to startup.
- M3c: sidebar never reflected the session name passed via `claude -n <name>`. Claude does not reliably emit a rename escape sequence on startup, so tmux's window name stayed at the shell default. `spawn.go` now parses `-n` / `--name` from the claude argv (`nameFromClaudeArgs`) and pre-seeds the tmux window name via the `new-window -n` / `new-session -n` flag at creation time; the sidebar reads `#{window_name}` as before and so picks up the label on the very first list-windows poll.
- M3c: surviving session preview garbled after closing another session. Tmux's "kill active window" switches the control client to the next window of the session, and that switch can dribble a partial redraw (cursor-positioned row rewrites without a `CSI 2J`) into the `%output` stream which then lands on top of the surviving pane's pre-close emulator state — producing a "mostly-right but with stale rows peeking through the gaps" view that only a manual resize could clean up. `handleWindowClosed` now invalidates every surviving pane's capture state (paneByWindow, paneTerminals, paneCaptured, paneCapturing, panePending) and clears `resolvedWindowID` so the `fetchSessions` round-trip immediately following the close naturally triggers a re-resolve + re-capture for the newly-highlighted survivor. The fresh capture-pane snapshot paints over the mixed state in one shot. New `TestWindowClosedMsgInvalidatesSurvivorPanes` pins the survivor-invalidation contract.

### Changed

- M3c: cleaned up debug-log scaffolding in `internal/tui/app.go`, `internal/tui/panes.go`, and `cmd/sm4c/cli/tui.go`. The `SM4C_DEBUG_LOG` facility in `debuglog.go` stays (zero cost when unset, invaluable for the next bug), but the per-render, per-keystroke, and per-emulator-write call sites that flooded the trace file during the freeze/distortion investigations are gone. Kept: Start OK/FAIL, bridge exit, backpressure drops, session-poll counts, pane resolve / capture / data chunk sizes. Removed: View start/end, renderSidebarView / renderRightPane step logs, handleKey per-focus dispatch traces, emu.Write / emu.Render start/end pairs, and the unused `previewBytes` helper.
- M3a-refinement: sm4c no longer exec-attaches into tmux from any code path. `sm4c [claude-args…]` still spawns a tagged claude window on the sm4c socket, but instead of handing the terminal to a raw `tmux attach-session` it opens the TUI focused on the freshly-spawned session (new `initialHighlight` hint threaded through `tui.Run` / `NewModel`). The TUI's `Enter` binding is now a deliberate no-op reserved for M3c's focus shortcut; there is no keystroke, CLI flag, or Action that drops the user into a bare tmux session. Rationale: the whole premise of sm4c is "one surface for concurrent claude sessions." If a user wants a raw `tmux attach`, they can use tmux directly. The `ActionAttachSession` intent, `Model.SelectedWindowID()`, `execAttach`/`execAttachReal`, `syscall.Exec`, and the old `spawnAndAttach` helper are all removed; `runTUI` and `runLaunch` funnel through a shared `openTUI` that runs the TUI in a re-entry loop — `n` (new session) now spawns a window outside the TUI and re-enters with that window as initial highlight, so the sidebar briefly blinks and redraws with the new row pre-selected rather than kicking the user out to tmux. Tests covering the old attach exec path (`TestTUIAttachActionExecsCorrectWindow`, `TestEnterOnHighlightedSessionEmitsAttachIntent`) are replaced with pins on the new behavior: Enter is inert, the initial-highlight hint snaps to matching sessions on first fetch, and the hint is retained across polls until a matching row appears (so a tmux indexing lag can't lose the target).
